# 掃描六個分析階段做了哪些檢測

> 對照程式：`backend/apps/scans/scanners.py`（`analyze_page` 與各 `analyze_*`）、`aeo/page_checks.py`、`geo_structure.py`、`security/secret_scanner.py`、`apps/agent/`。2026-10-10 依程式整理；規則改動時同步本檔。

## 先說結論：為什麼 SEO／AEO／GEO／UX／資安五個階段幾秒就跑完

這五個階段**不連線、不開瀏覽器**，只分析「爬取」階段已經抓回來、存在記憶體裡的資料。

| 工作 | 在哪個階段做 | 花多久 |
|---|---|---|
| 用真實 Chromium 打開每一頁、等畫面渲染完成、存 HTML | 爬取 | 每頁 1～5 秒 |
| 整頁截圖、行動版截圖 | 爬取 | 每頁約 1 秒 |
| 行動版寬度下量破版、觸控目標大小、欄位標籤 | 爬取 | 每頁約 1 秒 |
| 版面跳動（CLS）、JavaScript 錯誤 | 爬取 | 每頁同時收集 |
| axe-core 無障礙檢查（WCAG 2.0／2.1／2.2 A／AA） | 爬取 | 每頁 0.5～3 秒 |
| **把上面的 HTML 與量測結果逐條比對規則，產生問題** | **SEO／AEO／GEO／UX／資安** | **每頁每個維度約 1～30 毫秒** |

所以 20 頁 × 5 個維度＝100 次規則比對，加起來幾秒是正常的。慢的、需要連線的工作在其他階段：爬取、AEO 問答檢測、深度資安（TLS 憑證、DNS、Cookie）、連結檢查（最多 150 個連結、120 秒）、效能量測（Google PageSpeed，20～90 秒）、AI Agent（數分鐘）。

這不代表檢查比較隨便：規則比對本來就該很快，真正決定準確度的是規則本身與證據，不是花的時間。

---

## 1. SEO（逐頁，`analyze_seo`）

| 檢查 | 判定 | 嚴重度 |
|---|---|---|
| Meta title 長度 | 少於 10 或超過 65 字元 | 低 |
| Meta description | 沒有，或少於 50／超過 160 字元 | 低 |
| H1 數量 | 沒有 H1＝低；多個 H1＝資訊 | 低／資訊 |
| 圖片替代文字 | 有圖片沒寫 `alt`＝低；3 張以上大圖 `alt` 為空＝資訊 | 低／資訊 |
| canonical | 沒有 `<link rel="canonical">` | 資訊 |
| Open Graph | 缺 og:title／og:description／og:image／og:url 任一 | 低 |
| 結構化資料必填欄位 | 已有 JSON-LD，但缺 Google 複合式搜尋結果的必填欄位（依 Search Central） | 低 |
| 自評星等 | 商家自己標的評分不會顯示成搜尋星等 | 資訊 |

不檢查的頁面：登入／註冊／後台路徑、PDF 等檔案。整站層級的 SEO（失效連結、主網址不一致、重複標題、索引指示矛盾、robots.txt、sitemap）在後面的「連結檢查」階段。

## 2. AEO（逐頁，`aeo/page_checks.py`）

| 檢查 | 判定 | 嚴重度 |
|---|---|---|
| 不可被索引 | meta robots 或 `X-Robots-Tag` 有 `noindex` | 中 |
| 禁止摘要 | `nosnippet`、`max-snippet:0` | 中 |
| 部分段落禁止摘要 | 有 `data-nosnippet` 區塊 | 資訊 |
| JSON-LD 語法錯誤 | 結構化資料無法解析，整段會被忽略 | 中 |
| 標記與內容不一致 | 結構化資料寫的值（電話、地址、價格…）在頁面可見文字找不到 | 低 |

逐頁階段只做這些。AEO 的主要評分在後面的「AEO 問答檢測」：依網站內容出題（電話、Email、地址、營業時間、費用、報名、付款、退款、預約…），在所有頁面找答案並附原文證據，判定可回答／資訊不足／內容衝突／找不到。

## 3. GEO（逐頁，`analyze_geo`、`analyze_geo_fast`、`geo_structure.py`）

| 檢查 | 判定 | 嚴重度 |
|---|---|---|
| 沒有結構化資料 | 頁面沒有任何 JSON-LD | 低 |
| 實體類型不明確 | 有 JSON-LD 但沒有 Organization、Article 等明確實體 | 資訊 |
| 可引用段落偏少 | 成句段落少於 2 段或正文不到 300 字 | 資訊 |
| 內容依賴 JavaScript | 渲染後正文 ≥400 字，但原始 HTML 不到一半（多數 AI 爬蟲不執行 JS） | 中 |
| 沒有主內容區塊 | 沒有 `<main>` | 低 |
| 段落過長 | 有超過 1000 字的段落 | 低 |
| 長文沒有小標題 | 正文約中文 1500 字／英文 1000 詞以上，卻沒有 h2～h6 | 低 |
| 列舉沒用清單 | 同一段有 3 個以上編號 | 資訊 |

整站層級的 GEO（llms.txt、robots.txt 是否擋 AI 搜尋爬蟲、組織實體與 sameAs、文章作者與日期）在後面的「AI 爬蟲訊號」階段。

## 4. UX（逐頁，`analyze_ux`；量測在爬取時完成）

| 檢查 | 判定 | 嚴重度 |
|---|---|---|
| 行動版破版 | 手機寬度下頁面比螢幕寬（超過 4px），會出現水平捲動；溢出達螢幕寬一半為中 | 低／中 |
| 版面跳動（CLS） | >0.1＝低、>0.25＝中，並列出移動最多的元素 | 低／中 |
| 觸控目標過小 | 手機上可點元素寬或高 <40px；5 個以上升為中 | 低／中 |
| 表單欄位缺標籤 | input／select／textarea 沒有 label、aria、title 或 placeholder | 中 |
| JavaScript 錯誤 | 頁面有未捕捉的例外 | 中 |
| WCAG 無障礙（axe-core） | 對比不足、按鈕／連結沒有名稱、語言未設定等，axe 的 critical／serious 最高判中 | 低／中 |

觸控目標、缺標籤欄位與破版元素會在行動版截圖上框出實際位置。

## 5. 資安（逐頁，`analyze_security`、`analyze_data_exposure`、秘鑰偵測）

| 檢查 | 判定 | 嚴重度 |
|---|---|---|
| CSRF | 會改變狀態的表單（POST 或含密碼欄位）沒有 CSRF token | 中 |
| 身分證號、信用卡號 | **只看頁面上看得到的文字**；身分證過檢查碼，信用卡過 Luhn＋卡組織號碼規則＋卡片分組或附近有「卡號」等字（2026-10-10 修正：原本連圖片檔名、網址裡的數字都算） | 高 |
| 個人聯絡資料 | 手機、非本網站網域的 Email、藏在 HTML 註解裡的資料 | 中 |
| 公開的聯絡方式 | 本網域 Email、`mailto:`／`tel:` 連結（多半刻意公開，請確認） | 資訊 |
| 硬編碼秘鑰 | 頁面原始碼裡的私鑰、AWS／GitHub／Stripe 金鑰、含帳密的連線字串、JWT、明文密碼賦值 | 嚴重～中 |
| 瀏覽器用 Google 金鑰 | `AIza…` 金鑰本來就放在前端，只提醒確認已設參照網址與 API 限制（2026-10-10 由高改低） | 低 |

整站層級的資安在後面的階段：

- **站台資安**：HTTPS、HSTS、CSP、X-Frame-Options、X-Content-Type-Options。
- **深度資安**：TLS 憑證與協定、Cookie 旗標、CORS、CSP 品質、SRI、SPF／DMARC／DNSSEC、前端套件與伺服器版本的已知 CVE。
- **主動探測**：Nuclei／Katana、敏感檔案，只在主動模式且網域已驗證時執行。

## 6. AI Agent（`apps/agent/`，需要大型語言模型，數分鐘）

有兩種角色，執行條件不同：

| 角色 | 什麼時候跑 | 做什麼 |
|---|---|---|
| 擬真使用者 UX 測試 | **全網站**＋**勾 UX**（被動模式也跑） | 像真實訪客一樣看頁面、點主要按鈕、走表單與流程，回報卡住、看不懂、沒回應的地方。網域未驗證時只填欄位不送出，不在別人網站留資料 |
| 深度資安測試 | **全網站**＋**主動模式**＋**網域已驗證** | 先偵察網路請求，再派最多 6 位專家：登入與越權（IDOR）、注入（SQLi／XSS 等）、商業邏輯濫用、資訊洩漏、JWT、檔案上傳、密碼學 |

兩者都要平台總開關 `ARGUS_AGENT_ENABLED` 開啟。**單頁掃描不跑 Agent**（沒有流程可走），沒勾 UX 的被動掃描也不跑，所以進度條就不會出現「AI Agent」階段。
